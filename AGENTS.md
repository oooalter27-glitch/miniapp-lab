# Песочница мини-аппов — инструкция агенту

Здесь собираются мини-аппы для нашего билдера. Главное отличие от обычной
фронтенд-задачи: результат — не сайт, а **экраны, которые уезжают в кабинет**
и дальше правятся мышкой. Поэтому формат жёсткий, и отступать от него нельзя.

## Главное правило

Ты не имеешь права сказать «готово», пока `node scripts/screens.mjs check <имя>`
не даст ЗЕЛЕНО. Проверка идёт в две ступени: локальные правила и разбор тем же
парсером, что стоит на платформе. Красная проверка означает, что экран не
доедет до кабинета — значит работа не сделана.

## Цикл работы

1. Прочитай бриф в `brief/<имя>.md`.
2. `node scripts/screens.mjs new <имя>` — создаст `projects/<имя>/` из шаблона.
3. Пиши экраны в `projects/<имя>/screens/`: один файл — один экран,
   имена с номером (`01-hero.html`, `02-quiz.html`) — по ним строится порядок.
4. `node scripts/screens.mjs check <имя>` — до зелёного.
5. `node scripts/screens.mjs preview <имя>` — собирает `preview.html`,
   владелец открывает его двойным щелчком.
6. Отправку в кабинет (`push`) делает владелец или ты по его прямой просьбе.

## Формат экрана

Полная спека — `docs/SPEC.md`, читай её перед первым экраном. Коротко:

- экран = один `<section>`, ширина 375, контент сверху вниз;
- стили только inline через `style="…"`, размеры в px;
- никаких классов, `id`, `<style>`, `<script>`, `<link>`;
- разрешённые теги: section, div, ul, li, h1-h3, p, span, button, img;
- сложные блоки — через `data-craft`: carousel, leadform, quiz, video,
  rating, timer, progress. Их не верстай руками, билдер вставит свои.

Картинки не ищи и не скачивай: ставь `src="PLACEHOLDER_имя"`, а в `alt`
опиши, что должно быть на картинке — платформа берёт описание именно оттуда
и генерирует изображение при импорте. Пустой `alt` = картинка по имени файла,
то есть почти наугад.

## Чего не делать

- Не пиши React, Next и Tailwind. Это прошлый формат песочницы; он остался
  в `template/` и `scripts/lab.mjs` только для случаев, где нужна своя логика.
- Не придумывай теги и атрибуты вне спеки: парсер молча превратит их
  в пустой прямоугольник, и экран приедет в кабинет покалеченным.
- Не объявляй готовность по превью. Превью показывает браузер, а импортирует
  экран парсер — расходятся они именно на том, что ты сочинил сверх спеки.
- Не трогай `projects/*` старого формата (там `package.json` вместо `screens/`).

## Команды

    node scripts/screens.mjs login <ключ>    разовый вход на платформу
    node scripts/screens.mjs new <имя>       создать из шаблона
    node scripts/screens.mjs check <имя>     проверить (без зелёного работа не сделана)
    node scripts/screens.mjs preview <имя>   собрать preview.html
    node scripts/screens.mjs push <имя>      отправить экраны в кабинет

`check` и `push` ходят на платформу. Ключ задаётся один раз командой `login`
и лежит в домашней папке. Если ключа нет — скажи владельцу, не выдумывай обходных путей.

## Отчёт владельцу

Коротко: какие экраны собрал (списком), что показала проверка, где лежит
превью. Если чего-то из брифа не сделал — скажи прямо, что именно и почему.
