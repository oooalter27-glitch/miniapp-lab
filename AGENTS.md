# Песочница мини-аппов — инструкция агенту

Ты собираешь Telegram Mini App по брифу: от пустой папки до работающей ссылки.
Этот файл читается автоматически. Делай, как здесь написано, не изобретай свой
порядок.

## Главное правило

**Не говори «готово», пока не прошла проверка `node scripts/lab.mjs check <имя>`.**

Не «должно работать», не «код написан» — только после зелёной проверки.
Проверка гоняет типы и полную сборку. Если она красная, работа не сделана,
сколько бы файлов ты ни создал.

## Цикл работы

1. **Прочитай бриф** в `brief/<имя>.md`. Нет брифа — попроси заполнить
   `brief/TEMPLATE.md`, сам не выдумывай содержание за владельца.
2. **Покажи план экранов** до того, как писать код: список страниц, что на
   каждой, какие блоки берёшь готовыми. Дождись «ок».
3. **Создай проект**: `node scripts/lab.mjs new <имя>`. Руками папки не копируй.
4. **Собери экраны** из готовых блоков `template/src/components`. Новый
   компонент пиши, только если подходящего нет — и клади его туда же, чтобы
   следующий мини-апп им пользовался.
5. **Проверь**: `node scripts/lab.mjs check <имя>`. Красное — чини и гоняй снова.
6. **Покажи**: `node scripts/lab.mjs preview <имя>` и дай ссылку.
7. **Правки** — тем же циклом: правка → check → preview.
8. **Выкат** только по прямой команде владельца: `scripts/deploy.sh <имя>`.

## Чего не делать

- Не деплоить без явной просьбы. Сборка и превью — сколько угодно.
- Не трогать чужие проекты в `projects/` — только тот, над которым работаешь.
- Не менять `template/` посреди сборки проекта: правка шаблона затрагивает все
  будущие мини-аппы, это отдельная задача.
- Не тащить новые зависимости без нужды. Всё, что нужно для типового
  мини-аппа, уже стоит. Новый пакет — объясни зачем.
- Не хранить ключи и токены в коде. Только `.env.local`, который не в гите.

## Команды

Работают одинаково на Windows, macOS и Linux — это Node, а не bash:

```
node scripts/lab.mjs new <имя>
node scripts/lab.mjs check <имя>
node scripts/lab.mjs preview <имя> [порт]
```

Файлы `scripts/*.sh` — то же самое для Linux, на Windows их не зови.

## Что уже есть в шаблоне

Next.js 16 + React 19 + Tailwind 4 + TypeScript. Плюс:

- **Telegram WebApp SDK** подключён: `useTelegram()` отдаёт юзера, тему,
  кнопки. Работает и в браузере — там подставляется заглушка, чтобы можно
  было отлаживать без Telegram.
- **Библиотека блоков** в `src/components`: заголовки, карточки услуг и
  кейсов, тарифы, FAQ, шаги процесса, форма заявки, нижний CTA, кнопка.
  Смотри `docs/PLAYBOOK.md` — там что из чего собирается.
- **Приём заявок**: `LeadForm` шлёт на `/api/lead`, оттуда в Telegram
  владельцу. Настраивается двумя переменными в `.env.local`.

## Как проверять себя, кроме сборки

Сборка ловит типы и синтаксис, но не ловит пустой экран. Поэтому:

- после `preview` дёрни `curl -s localhost:<порт>/<путь> | head -40` по
  каждой странице и убедись, что там есть твой текст, а не заглушка Next;
- проверь, что каждая кнопка куда-то ведёт: пустой `href="#"` — это недоделка;
- посмотри страницу в узком окне (мини-апп открывается на телефоне): блоки не
  должны разъезжаться. Для этого в шаблоне все отступы и сетки уже
  заданы мобильными — не ломай их произвольными фиксированными ширинами.

## Отчёт владельцу

Коротко и по делу:

- что собрал: страницы списком;
- ссылка на превью;
- что осталось нерешённым или требует его решения;
- если что-то в брифе противоречило само себе — скажи прямо, а не выбирай
  молча.

Не перечисляй файлы, которые создал. Владельцу важен результат, а не дерево
каталогов.
