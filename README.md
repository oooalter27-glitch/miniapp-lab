# Песочница мини-аппов

Чтобы собрать мини-апп, не переписывая код из чата руками. Заполняете бриф —
агент создаёт проект, собирает экраны, сам себя проверяет и отдаёт ссылку.

## Как пользоваться

```bash
# 1. Опишите задачу
cp brief/TEMPLATE.md brief/my-app.md && $EDITOR brief/my-app.md

# 2. Позовите агента в этой папке
codex

#    и скажите: «Собери мини-апп по brief/my-app.md»
```

Дальше он работает сам: создаёт проект, собирает, проверяет и показывает
превью. Правки — обычными словами в том же разговоре.

## Что внутри

| Папка | Что |
|---|---|
| `AGENTS.md` | Инструкция агенту. Читается им автоматически |
| `brief/` | Брифы: по одному файлу на мини-апп |
| `template/` | Скелет: Next 16, Tailwind 4, Telegram SDK, 12 готовых блоков |
| `projects/` | Сюда создаются мини-аппы |
| `scripts/` | Создать, проверить, показать, выкатить |
| `docs/PLAYBOOK.md` | Из чего собирать экраны |

## Команды

Везде — Windows, macOS, Linux:

```bash
node scripts/lab.mjs new my-app        # создать проект из шаблона
node scripts/lab.mjs check my-app      # типы + сборка (без зелёного — работа не сделана)
node scripts/lab.mjs preview my-app    # поднять и открыть (Ctrl+C — стоп)
```

Только Linux/macOS — те же действия на bash плюс выкат:

```bash
scripts/deploy.sh my-app               # выкатить на сервер (по вашей команде)
```

## Что уже работает из коробки

- **Telegram SDK** — юзер, тема, кнопки. В браузере подставляется заглушка,
  поэтому отлаживать можно без телефона.
- **Заявки** — форма шлёт на `/api/lead`, оттуда в Telegram владельцу.
  Две строки в `.env.local`:
  ```
  MINIAPP_BOT_TOKEN=токен бота
  MINIAPP_OWNER_CHAT_ID=ваш id
  ```
  Не заданы — ручка честно вернёт ошибку, и человек её увидит. Тихой потери
  заявок нет by design.
- **Проверка подписи** initData: за клиента нельзя прислать чужие данные.

## Почему агент не «сказал готово» раньше времени

В `AGENTS.md` записано главное правило: без зелёного `check.sh` работа не
считается сделанной. Проверка гоняет типы и полную сборку — то, что ловит
несуществующие пропсы и сломанные импорты. Это же правило требует после
превью дёрнуть каждую страницу и убедиться, что на ней ваш текст.

## Деплой

`deploy.sh` кладёт проект в `/opt/miniapps/<имя>` на play2go, ставит
зависимости, собирает и поднимает в pm2 на свободном порту из 3410–3499.

Caddyfile скрипт **не правит** — печатает готовый блок для вставки. Конфиг
общий на весь сервер, там живут клиентские проекты; автоматическая правка
чужого боевого файла того не стоит.
