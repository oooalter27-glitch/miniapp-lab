# Песочница мини-аппов

Собрать мини-апп словами и перенести его в кабинет двумя командами.
Экраны сразу пишутся в формате нашего билдера, поэтому переносить нечего
конвертировать — они просто уезжают в проект и открываются для правки мышкой.

## Как пользоваться

    # 1. Опишите задачу
    cp brief/TEMPLATE.md brief/my-app.md    # и заполните

    # 2. Позовите агента в этой папке
    codex
    #    «Собери мини-апп по brief/my-app.md»

Дальше он создаёт проект, пишет экраны и проверяет себя. Вам остаётся
посмотреть превью и отправить в кабинет.

## Команды

    node scripts/screens.mjs login <почта> <пароль>   вход в кабинет
    node scripts/screens.mjs new <имя>       создать из шаблона
    node scripts/screens.mjs check <имя>     проверить экраны
    node scripts/screens.mjs preview <имя>   собрать preview.html
    node scripts/screens.mjs push <имя>      отправить в кабинет

`check` и `push` ходят на платформу. Вход — один раз командой `login`
теми же почтой и паролем, что и в кабинет; сессия хранится в домашней папке,
вне репозитория. Адрес по умолчанию — miniapp.alterda.ru, меняется `MINIAPP_URL`.

Перед отправкой впишите `projectId` в `projects/<имя>/meta.json` — это проект
в кабинете, куда лягут экраны.

## Что внутри

| Папка | Что |
|---|---|
| `AGENTS.md` | Инструкция агенту, читается им автоматически |
| `brief/` | Брифы: по одному файлу на мини-апп |
| `docs/SPEC.md` | Формат экрана: теги, стили, готовые блоки |
| `template-screens/` | Скелет проекта экранов |
| `projects/` | Сюда создаются мини-аппы |
| `scripts/screens.mjs` | Все команды |

## Прошлый формат

`template/` и `scripts/lab.mjs` — прежняя песочница на Next. Она осталась для
редких случаев, где нужна своя логика, которую билдер не умеет: там получается
самостоятельное приложение, но в кабинет оно не переносится.
